# PRD: 2モード設計

作成日: 2026/05/04  
最終更新日: 2026/05/04  
担当: internal prototype

## ■サマリ

- 本プロトタイプは、同じ特別支援ケースライブラリを2つの目的で使い分ける。
- モード1は、PdM/プロダクト開発者が先生のペインと潜在ニーズを探索するための「ペイン深掘りモード」。
- モード2は、支援員や現場初学者が問題行動をABC分析で整理し、支援方針を学ぶための「ABC分析・支援学習モード」。
- 当面のMustは、モード選択、ケース共通利用、モード別の問い、モード別の振り返り出力。
- 初期実装では探索的ニーズ発見を優先し、既存仮説/ユーザーストーリーの妥当性検証は後続扱いにする。

## ■機能概要

| 領域 | 概要 |
|------|------|
| モード選択 | 起動時に「ペイン深掘り」「ABC分析・支援学習」を選べる |
| 共通ケースライブラリ | 同じケースを、PdM向け/支援学習向けの異なる問いで扱う |
| ペイン深掘りモード | 先生の意思決定、諦め、構造的制約、ニーズ仮説を抽出する |
| ABC分析モード | A:先行事象、B:行動、C:結果を整理し、支援案を考える |
| ケース追加 | 顧客要望や現場知見に対応するケースを追加し、妥当性を検討できる |
| 出力 | ペインマップ、ニーズ仮説、ABC整理、支援案、観察ポイントをMarkdownで出力する |

## ■背景・課題

### 背景（As-is）

- 現在のプロトタイプは、特別支援の先生の1日や重要場面を選択式で追体験できる。
- ケースは複数あり、選択によってペインタグ、メーター、判断ログが残る。
- ただし、現在は「顧客理解」と「支援学習」が同じ体験に混在している。
- 社内トライアルでは、PdMが顧客理解を深める用途と、支援員が支援方法を学ぶ用途の両方に可能性がある。

### 課題（Gap）

- PdMが知りたい「どこにペイン/潜在ニーズがあるか」と、支援員が知りたい「どう支援を組み立てるか」は問いが異なる。
- 現在の振り返りだけでは、探索的にニーズを掘り起こす作業にはまだ浅い。
- ABC分析を学びたい初学者にとっては、A/B/Cを自分で整理する足場が不足している。
- 顧客要望に対応するケースを追加しても、それが本当に妥当なケースか評価する仕組みがない。

## ■目的・目標

### 目的（To-be）

同じケースライブラリを、プロダクト探索と支援学習の2つのレンズで使えるようにし、社内の顧客理解と支援知識の学習を促進する。

### 目標

| 指標 | 定義方針 | 備考 |
|------|----------|------|
| ペイン抽出数 | 1ケース体験後にPdMが言語化できるペイン/制約/諦めの数 | 初期は定性的に確認 |
| ニーズ仮説数 | 1ケース体験後に生成されるプロダクト仮説の数 | 質はレビューで確認 |
| ABC理解 | 初学者がA/B/Cを分類し、支援案を1つ以上説明できるか | 正誤より説明可能性を重視 |
| ケース妥当性 | 追加ケースが実際の先生レビューで「ありそう」と評価されるか | 後続検証 |

## ■ターゲットユーザー

| ペルソナ | 役割・状況 | 得たい価値 |
|----------|------------|------------|
| PdM/プロダクト開発者 | 特別支援領域の顧客理解を深めたい。現場経験は限定的 | 先生のペイン、潜在ニーズ、プロダクト機会を見つけたい |
| 社内支援員/初学者 | 支援の考え方をケースで学びたい | 問題行動をABC分析で整理し、支援の選択肢を考えられるようになりたい |
| 現場知見者/レビュー協力者 | ケースの妥当性を見たい | ケースが実態に近いか、誤解を生まないかを判断したい |

## ■ユースケース

| No. | 誰が | きっかけ | 操作 | 得られるもの |
|-----|------|----------|------|--------------|
| 1 | PdM | 顧客理解を深めたいとき | ペイン深掘りモードでケースを体験し、問いに答える | ペインマップ、ニーズ仮説、追加調査観点 |
| 2 | PdM | 顧客要望を受け取ったとき | 要望に対応するケースを追加/選択し、どの場面のペインかを見る | 要望の背景仮説、妥当性メモ |
| 3 | 支援員初学者 | 支援方法をケースで学びたいとき | ABC分析モードでA/B/Cを分類し、対応案を選ぶ | ABC整理、支援案、観察ポイント |
| 4 | 現場知見者 | ケース内容をレビューするとき | ケースと出力を見て、実態とのズレを指摘する | ケース改善メモ、リスク指摘 |

## ■要件・仕様

### 機能要件

| 機能 | ユーザーストーリー | 優先度（開発） | 備考 |
|------|--------------------|----------------|------|
| モード選択 | PdM/支援員は目的に合うモードを選びたい。なぜなら、顧客理解と支援学習では見るべき問いが違うからだ。 | 高 | 最初の画面に置く |
| ペイン深掘り問い | PdMはケース体験中に「何を諦めたか」「どの制約が構造的か」を考えたい。なぜなら、表面的な忙しさではなくニーズの源泉を見つけたいからだ。 | 高 | 進化論マーケティング的な顧客没頭ワークを参考にするが、本文引用ではなく独自の問いに落とす |
| ペインマップ出力 | PdMはケース後にペインを分類して見たい。なぜなら、プロダクト機会や次の調査観点へつなげたいからだ。 | 高 | 時間、記録、保護者、校内連携、支援設計など |
| ニーズ仮説出力 | PdMは体験からニーズ仮説を生成したい。なぜなら、次のインタビューやMVP仮説に接続したいからだ。 | 高 | 初期は探索型に寄せる |
| 既存仮説検証 | PdMは既存のユーザーストーリーや顧客要望をケースに照らしたい。なぜなら、要望の背景ペインが妥当か見たいからだ。 | 中 | 今回は後続 |
| ABC分類 | 支援員初学者はケース内のA/B/Cを分類したい。なぜなら、行動を背景と結果の関係で捉える練習をしたいからだ。 | 高 | A/B/Cの説明を画面内に出す |
| 支援案選択 | 支援員初学者は事前支援、その場の対応、事後対応を選びたい。なぜなら、問題行動だけでなく環境調整まで考えたいからだ。 | 高 | 正解判定より理由の理解を重視 |
| 発達特性ベースのケース拡充 | PdM/支援員は発達特性に基づく複数ケースを体験したい。なぜなら、支援の観点がケースごとに変わることを理解したいからだ。 | 中 | ラベルは慎重に。診断名で断定しすぎない |
| Markdown出力 | 利用者は体験結果をMarkdownでコピーしたい。なぜなら、社内共有や次のPRD/インタビュー設計に使いたいからだ。 | 高 | 既存機能を拡張 |

### 非機能要件

| 区分 | 要件 | 内容 |
|------|------|------|
| ローカル実行 | 外部パッケージ不要 | 社用PCで動かすため、HTML/CSS/JSのみで維持 |
| 安全性 | 実在児童情報を扱わない | ケースは架空。実データ入力欄は初期MVPでは作らない |
| 表現配慮 | 子どもを問題として描かない | 行動の背景、環境、支援体制、先生の制約に焦点を置く |
| 学習姿勢 | 正解/不正解で断定しすぎない | ABC分析モードでも、仮説と観察ポイントを重視 |
| 観測性 | 体験結果を後で見返せる | ログとMarkdown出力を維持 |

### やらないこと

- 初期実装ではログイン、サーバー保存、外部API連携は扱わない。
- 実在児童の記録入力や医療/診断的な判定は扱わない。
- ABC分析モードを専門家向けの高度な行動分析ツールにはしない。
- 発達特性を固定的なステレオタイプとして描かない。

## ■開発優先順位

高（must）: 2モード化の核。体験価値が成立するために必要。  
中（want）: ケース拡充や検証支援。初期後半で入れたい。  
低（should）: 共有性や便利機能。後続でよい。

| 優先度 | 領域・機能 |
|--------|------------|
| 高（must） | モード選択、ペイン深掘り問い、ペインマップ出力、ABC分類、支援案選択、Markdown出力 |
| 中（want） | 既存仮説検証、発達特性ベースのケース拡充、ケース妥当性チェック |
| 低（should） | 結果比較、複数ケース横断分析、印刷用レポート |

## ■リスク

| リスク | 緩和 |
|--------|------|
| 子どもを「問題行動の主体」として単純化してしまう | 行動の背景、環境、前後関係、支援体制を必ずセットで扱う |
| ABC分析が正解当てゲームになる | 「もっともらしい仮説」「追加で観察すべきこと」「対応のリスク」を返す |
| PdM向け探索と支援員向け学習が混線する | 起動時にモードを分け、問いと出力を完全に分ける |
| 発達特性ケースがステレオタイプ化する | 診断名より「困りの現れ方」「環境との相互作用」でケースを設計する |
| ケースの現実味が不足する | 先生/支援員レビューを前提に、ケース妥当性メモを持つ |

## ■残論点

| 論点 | メモ |
|------|------|
| ペイン深掘りの問いセット | 顧客没頭、制約、諦め、感情、本能/欲求、プロダクト機会のどこまで入れるか |
| ABC分析のフィードバック粒度 | 初学者向けにどこまで解説するか |
| 発達特性ケースの分類軸 | ADHD/ASD/LD等の名称を前面に出すか、困りの状況ベースにするか |
| ケース追加の妥当性評価 | 先生レビュー用のチェック項目をどうするか |
| 既存仮説検証モード | 探索モードとは別機能にするか、ペイン深掘りモード内のサブタブにするか |
