# Plan

## Goal
Create a small local browser simulation where the same special-support case library can be used for two modes: product discovery and beginner ABC-analysis learning.

## Audience
- Primary: PdM/product developer building customer understanding.
- Secondary: beginner support staff learning how to organize situations with ABC analysis.

## Product Modes
- ペイン深掘りモード: PdMが先生のペイン、諦め、制約、潜在ニーズを探索する。
- ABC分析・支援学習モード: 初学者がA/B/Cで行動を整理し、支援案と観察ポイントを学ぶ。

## MVP
- Case library with multiple fictional special-support situations.
- Each case is split into short scenes.
- 3 choices per scene.
- Meters for child安心, class stability, parent trust, teacher energy, time, and records.
- Pain tags that accumulate from choices.
- End-of-case reflection that explains trade-offs.
- Markdown export for sharing insights.
- Mode selection on the start screen.
- Pain deep-dive cards at the end of product discovery mode.
- ABC card classification mode for a first peer-conflict/impulsivity case.

## Current Cases
- 通常級と支援のはざまの一日: baseline day with time pressure, child support, parent communication, and records.
- 登校しぶりと家庭の不安: morning phone call, delayed arrival, afternoon relapse, next-day plan.
- 保護者との認識ズレ: event interpretation gap between school and home.
- 交流学級との連携: inclusion, coordination, accommodations, and expectations.
- 行動の背景を探る: sensory triggers, hypothesis building, and careful record sharing.
- ケース会議前夜: fragmented records, stakeholder disagreement, and implementation planning.
- 校外学習前日の準備: risk planning, parent anxiety, role division, and preview support.
- 通級の先生の一日: daily resource-room instruction, short sessions, records, and return-to-class handoff.
- 通級と在籍学級の連携: connecting resource-room findings to homeroom practice.
- 時間割のすき間で支える: schedule changes, urgent consultations, multiple students, and limited resource-room time.
- 明日の個別課題を選ぶ: selecting and tuning materials from prior observations.
- 同じ教材を使い回せない: balancing reuse, individualization, and material management.
- 授業後に次回を組み直す: turning lesson reactions into next-session design.

## Not Now
- Login or data storage.
- Real student records.
- Specific disability diagnosis simulation.
- Scoring teachers as good/bad.
- External packages or deployment.
- Expert-level behavior analysis.
- Medical or diagnostic judgement.

## Verification
- Manual browser check.
- Confirm case selection works.
- Confirm mode selection works after implementation.
- Confirm every choice has visible consequences.
- Confirm final reflection supports customer understanding or beginner learning rather than judging the player.
